The positive claim is in good shape and the negative boundary is unusually well established. What decides whether this lands in a strong venue is no longer the model. It is whether the headline number survives the honest metric, whether "serious" means anything clinically, and whether we open the one direction that is genuinely new. That is the three tasks below, and they are independent enough to run in parallel.

Task 1

Make the headline survive AP and full coverage

Highest risk to the claim

The transfer lift is currently reported as macro-AUROC over 29% of the rare labels. Both halves of that sentence are attackable, and a reviewer will attack them together.

The two objections

  • AUROC is optimistic under extreme imbalance. With a handful of positives against tens of thousands of negatives, AUROC can look strong while precision is near zero. Average precision is the metric that reflects what a pharmacovigilance user actually experiences.
  • 29% coverage. The rare-band mean is taken over the minority of rare labels that had enough test positives to score. If the evaluable 29% are systematically the easier, more frequent end of the rare band, the reported lift is measured on the friendliest slice of the tail.

What to run

StepDetail
Re-reportSame 9-seed paired transfer vs isolation comparison, now reporting macro-AP next to macro-AUROC, using the corrected bootstrap (label set fixed before resampling).
Coverage sweepRecompute the lift as a function of the minimum-test-positives rule that defines "evaluable". Plot delta against coverage from the current 29% outward.
Position checkWithin the rare band, correlate per-label lift with the label's train frequency. If the lift concentrates at the frequent edge, say so explicitly.
If it holds: the claim becomes "transfer lifts the tail on the honest metric across coverage levels", which is a materially stronger sentence than the one we have now.
If it does not hold: that is the finding, and it must be reported. A transfer effect that exists on AUROC but vanishes on AP is a real and publishable negative about how tail DDI work is evaluated. Either way we end up with something defensible, which is the point of running it first.
Task 2

Ground "serious" in clinician severity, not keywords

Weakest link in the clinical claim

Right now a side effect counts as serious because severity.py matched a keyword in its MedDRA term. Every clinical claim in the paper rests on that heuristic. DDInter, which carries clinician-assigned severity, is already sitting in the repo at data/external/ddinter/.

What to run

StepDetail
MapResolve DDInter drug pairs onto the TWOSIDES pair universe through the existing drug_resolver, and record the match rate honestly.
AgreeQuantify agreement between the keyword heuristic and the clinical severity: confusion matrix and Cohen's kappa. This number goes in the paper whatever it is.
Re-stateRe-run the serious-rare transfer result with the serious set defined clinically instead of by keyword, and compare the two versions of the claim side by side.
The real difficulty, worth the first ten minutes of the meeting: DDInter severity is assigned to a drug pair (this combination is major or moderate), while our severity label is attached to a side effect (rhabdomyolysis is serious). These are not the same object and cannot be joined naively. Options are to define a pair-level serious outcome and reframe the claim at pair level, or to keep the effect-level claim and use DDInter only as external validation on the pairs where both exist. This choice changes what the paper claims, so it is a decision for the two of you, not something to settle in code.
Payoff: it converts "serious by our keyword rule" into "serious by clinician assignment", which is the difference between a methods paper and a clinically credible one.
Task 3

Population localization of interaction risk

The genuinely new direction

The one direction that is new rather than corrective, and it lives in the warm setting where the model demonstrably works. Question: for a known drug pair and a known adverse event, does the strength of the signal differ across populations by more than reporting volume explains?

Why it fits this project

  • It does not fight the cold-start boundary. It is a different problem: subgroup variation among known drugs, which is exactly where the model has signal.
  • The disproportionality machinery is already built. research/disproportionality.py has PRR, ROR and the Bayesian IC with standard cutoffs, so the statistics exist and only the stratification is new.
  • If it works it is a separate paper and a distinct research identity, not an increment on the current one.

What to run

StepDetail
AcquireRaw FAERS quarterly files, which carry age, sex and reporting country. This is the actual work of the task.
StratifyRecompute the disproportionality statistics within subgroups for pairs that already show a signal overall.
ControlNegative controls before any claim: pairs with no plausible subgroup mechanism must show no subgroup difference. Without this the whole result is reporting bias.
State the limits up front. TWOSIDES as distributed is aggregated and carries no demographics, so this needs the raw FAERS files and is the only one of the three tasks with a data-acquisition dependency. Confounding is severe: country, age and sex all drive who reports what, not only who reacts to what. Any subgroup difference we find is a difference in reporting until the negative controls say otherwise. Ancestry is not in FAERS at all, so reporting country is a crude and contestable proxy and should be described as one.

Code corrections already made

Five defects in the evaluation and loss layer, each of which was quietly moving a reported number. All 140 existing tests still pass, and 13 new tests pin these behaviours.

WhereWhat was wrongWhy it matters
metrics.py
severity		 The serious set was recomputed from a 0.6 quantile of the weight vector, overwriting the intended rule on the line above it. The quantile included zero-weight unmapped labels. The safety metric did not use the same definition of serious as the training code. Numbers from before the fix are not comparable.
metrics.py
coverage		 Macro scores were returned without the denominator they were averaged over. Coverage now travels with every macro score and every band. This is what Task 1 measures against.
metrics.py
bootstrap		 Row resampling silently changed which labels were scorable, so each replicate averaged a different label set. Confidence intervals were systematically narrow, because the labels dropping out were the unstable ones. The label set is now fixed first and residual drift is reported.
losses.py
DB loss		 The negative-tolerant term omitted the 1/lambda factor from Wu et al., so at the default lambda = 5 every negative carried five times its intended weight. Backwards for a loss whose purpose is stopping rare-class negatives from swamping the gradient. Old behaviour is still reachable via faithful_ntr=False.
losses.py
ASL		 Gradient flowed through the focusing weight, which the reference implementation detaches by default. Known instability source on heavily imbalanced label sets. Loss value is unchanged, gradient is not.
models.py
band heads		 Labels claimed by no frequency band were emitted as -inf, giving a constant score that scored as AUROC 0.5. The model was credited with guessing on labels it was never allowed to predict. Now finite, flagged through covered_mask, and warned about at construction.
